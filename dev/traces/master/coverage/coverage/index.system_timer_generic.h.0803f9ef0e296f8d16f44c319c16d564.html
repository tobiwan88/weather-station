7 /**
8 * @file
9 * @brief Generic tickless system-timer core
10 *
11 * This header carries the tick accounting that every tickless system-timer
12 * driver would otherwise reimplement by hand: the cycle-to-tick conversion, the
13 * announce baseline (last_cycle / last_tick / last_elapsed), the deadline
14 * computation and the range clamp. A driver reduces to a few cycle-domain
15 * primitives; the tick contract the kernel calls (sys_clock_set_timeout(),
16 * sys_clock_elapsed(), sys_clock_cycle_get_32/64()) is emitted here.
17 *
18 * The file is an implementation header, not a normal declaration header: it
19 * *defines* the global sys_clock_* entry points. Any number of drivers can be
20 * built on it; each includes it once, after providing its own constants and
21 * primitives. A build compiles a single system-timer driver, so those
22 * definitions land once.
23 *
24 * A driver, before the include, provides:
25 *
26 * - Exactly one backend feature macro:
27 * TIMER_CORE_BACKEND_COMPARE_ORDERED free-running counter plus an absolute
28 * compare register whose match is an ordered
29 * comparison: the interrupt fires once the counter
30 * reaches or has passed the value, so a target
31 * already in the past fires at once (arm_arch,
32 * riscv_machine, ...). The usable range is half
33 * the counter width, which is what
34 * TIMER_CORE_ALARM_MAX_CYCLES bounds.
35 * TIMER_CORE_BACKEND_COMPARE_EXACT the same hardware shape, but the match
36 * is on equality only: a target written after the
37 * counter has passed it is missed for a whole
38 * counter period (hpet, mips_cp0, ...). The core
39 * writes such a comparator through a verify loop
40 * (see timer_core_set_compare()), so the
41 * driver needs no minimum-delay floor of its own.
42 * TIMER_CORE_BACKEND_RELOAD a counter that fires after a relative
43 * delay (down-counters, compare-match-reset
44 * periodics). Assumed to auto-reload: on a
45 * non-tickless kernel it free-runs from the LOAD
46 * set at init and is not reprogrammed per tick.
47 *
48 * If arming requires the timer interrupt to be enabled, enable it inside the
49 * arming primitive rather than tracking it separately. The core does not model
50 * interrupt masking.
51 *
52 * - static uint32_t/uint64_t timer_driver_cycle_get(void): the hardware cycle
53 * count. Its rate is TIMER_CORE_CYCLES_PER_SEC (see the knobs below), by default the
54 * kernel system clock rate. Return the raw counter, even a narrow one that wraps:
55 * declare its width with TIMER_CORE_COUNTER_WIDTH and the core masks every delta to
56 * that width, so the driver never has to widen the count in software. The return
57 * width is the driver's, as with the arming primitives above: uint32_t for a counter
58 * of TIMER_CORE_COUNTER_WIDTH 32 or less, uint64_t for a wider one. The core narrows
59 * what it reads to the declared width anyway, so returning the register's own type
60 * spares a 32-bit target the widening.
61 *
62 * - the arming primitive for the chosen backend:
63 * COMPARE: static void timer_driver_set_compare(uint32_t/uint64_t cycles)
64 * Write the comparator so an interrupt fires when the counter
65 * reaches @p cycles, a full-width cycle count. The argument width
66 * is the driver's: a 64-bit comparator takes uint64_t; a 32-bit
67 * one may take uint32_t (or mask a uint64_t argument) to drop the
68 * value to its comparator width. A plain register write is all
69 * that is wanted here: with COMPARE_ORDERED the hardware handles a
70 * past target itself, and with COMPARE_EXACT the core wraps this
71 * in the verify loop that deals with it.
72 * RELOAD: static void timer_driver_set_reload(uint32_t/uint64_t cycles)
73 * Fire an interrupt after @p cycles more cycles. The core has
74 * already clamped @p cycles to [TIMER_CORE_ALARM_MIN_CYCLES,
75 * TIMER_CORE_ALARM_MAX_CYCLES]. The argument width is the driver's:
76 * uint32_t suits a counter whose TIMER_CORE_ALARM_MAX_CYCLES fits 32
77 * bits (the usual case); a wider counter may take uint64_t and
78 * raise TIMER_CORE_ALARM_MAX_CYCLES to match. The core does not narrow
79 * the value, so the two must be kept coherent.
80 *
81 * Optional knobs (sensible defaults provided):
82 *
83 * - TIMER_CORE_CYCLES_PER_SEC: rate, in Hz, of the counter timer_driver_cycle_get() reads,
84 * from which the core derives the cycles per tick. Defaults to the kernel
85 * system clock rate; a driver whose counter runs at another rate (prescaled,
86 * or a fixed frequency) overrides it. With a build-time-constant rate the
87 * derived cycles-per-tick is a constant (the tick math divides by it on the
88 * announce path); with a run-time rate
89 * (CONFIG_TIMER_READS_ITS_FREQUENCY_AT_RUNTIME) the core precomputes it once
90 * in timer_core_init(), so that path never divides the rate twice.
91 * The core derives TIMER_CORE_CYC_PER_TICK from it, which a driver may read
92 * for its own hardware setup but never defines itself.
93 * - TIMER_CORE_CYCLES_PER_SEC_RUNTIME: define when the override above is a
94 * variable rather than a build-time constant, a rate read from the clock
95 * controller at init say. The core then precomputes the cycles per tick the
96 * same way it does for CONFIG_TIMER_READS_ITS_FREQUENCY_AT_RUNTIME. The
97 * variable must hold its final value before timer_core_init() is called.
98 * - TIMER_CORE_COUNTER_WIDTH: width, in bits, of the count timer_driver_cycle_get()
99 * returns, up to 64. Defaults to the native register width, which suits any
100 * counter at least that wide; a counter of another width, including a 64-bit one
101 * on a 32-bit CPU, states its own. The core masks every delta to this width,
102 * which is what lets a narrow counter be returned raw.
103 * - TIMER_CORE_COUNTER_NONMONOTONIC: define if the counter may momentarily read
104 * behind a value already observed (e.g. a global timer under QEMU SMP); the
105 * core then treats a backwards read as no elapse instead of a huge jump.
106 * - TIMER_CORE_COUNTER_NONATOMIC: define when timer_driver_cycle_get() is not a
107 * single atomic read but a synthesized count (built from a shared software
108 * accumulator the ISR and reprogram paths also touch). The core then reads
109 * it under the clock lock in sys_clock_cycle_get_32/64() instead of raw.
110 * - TIMER_CORE_HAVE_CYCLE_GET_32 / _64: define (and provide your own
111 * sys_clock_cycle_get_32 / _64) to suppress the core's, e.g. when the raw counter
112 * needs scaling. timer_core_cycle_get(), available after the include, gives the
113 * full-width count in the counter's own domain to scale from. The 32-bit one is
114 * required of a driver that sets TIMER_CORE_CYCLES_PER_SEC, since a counter
115 * running at a rate of its own is one the kernel cannot read raw. The core then
116 * emits no 64-bit getter either, that being in the domain the driver just
117 * declared foreign; supply one as well to have it.
118 * - TIMER_CORE_ALARM_MAX_CYCLES: largest value the arming primitive can express,
119 * nothing more. Defaults to the whole span of TIMER_CORE_COUNTER_WIDTH, the alarm and
120 * the counter usually being the same hardware. Set it where the arming range is
121 * decided by something else: a compare or reload register narrower than the counter,
122 * or a separate device. It is a statement about the hardware, so it carries no
123 * safety margin; the core derives its own from TIMER_CORE_COUNTER_WIDTH.
124 * - TIMER_CORE_ALARM_MIN_CYCLES (RELOAD): reload floor, in cycles.
125 * - TIMER_CORE_ALARM_LEAD_CYCLES (COMPARE_EXACT): cycles a compare must be ahead of
126 * the counter for the match to be caught. Defaults to 1. Raise it for hardware
127 * that carries the write into the counter's clock domain first.
128 * The driver completes with its IRQ handler (a hardware acknowledge, then
129 * timer_core_announce()), its init (connect the IRQ, then timer_core_init()) and,
130 * on SMP, an smp_timer_init() that primes the per-CPU timer via
131 * timer_core_smp_prime().
132 */
