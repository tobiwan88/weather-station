518 * - If you have multiple static assertions in the same scope,
519 * `gcc -Wredundant-decls` complains.
520 * - When the assertion fails, some compilers complain about a negative
521 * bit-field width without displaying the problematic line, so the message
522 * is not visible.
523 *
524 * On Godbolt compiler explorer, the only failures I could find are:
525 * - CCC (Claude C Compiler) as of 2026-03-02 ignores the assertion.
526 * - Chibicc 2020-12-07 ignores the assertion.
527 * - LC3 (trunk) ignores the assertion.
528 * - MSVC warns about assertions, whether they pass or not:
529 * "warning C4116: unnamed type definition in parentheses"
530 * This doesn't matter because non-ancient MSVC supports __COUNTER__,
531 * which is covered above.
532 * - ppci 0.5.5 complains of a syntax error.
533 * - SDCC 4.5.0 (and earlier) complains if there are multiple assertions in
534 * the same scope, even if they pass:
535 * "extern definition for 'mbedtls_static_assert_anchor' mismatches with declaration."
536 * - x86 tendra (trunk) complains if there are multiple assertions in
537 * the same scope, even if they pass:
538 * " The types 'int ( * ( void ) ) [<exp1>]' and 'int ( * ( void ) ) [<exp2>]' are incompatible."
539 * - vast (trunk) complains about assertions at function scope,
540 * even if they pass:
541 * "unexpected error: failed to legalize operation 'll.func' that was explicitly marked illegal"
542 * This doesn't matter because it supports __COUNTER__, which is covered
543 * above.
544 */
545 #define MBEDTLS_STATIC_ASSERT(expr, msg) \
546 extern int (*mbedtls_static_assert_anchor(void))[sizeof(struct { \
547 int STATIC_ASSERT : (expr) ? 1 : -1; \
548 })]
549 #endif
